779: - `--workspace` selects a workspace and `--package` selects one member. A
780:   workspace with one member may omit `--package`; a multi-member workspace must
781:   not choose implicitly. A source-free build inside a declared member discovers
782:   the enclosing workspace and selects that member.
783: - Local modules resolve relative to the selected product root. The dependency
784:   name is its first module-path segment; a one-segment import selects its root
785:   product and deeper paths resolve beneath that product's source directory.
786: - Workspace package metadata includes every member, but compilation starts
787:   from only the selected product's root source and recursively loads its
788:   imports. Unimported member sources are not parsed and do not supply program
789:   entry points. Every loaded source retains its package identity and resolves
790:   imports through that package's own direct dependencies. A dependency root
791:   must declare the imported namespace and contain no executable top-level
792:   statements. Module import cycles are rejected.
793:   Source diagnostics preserve the lexical/parser boundary: lexical failures
794:   report their line and column without a file prefix, while parser failures
795:   include the loaded source path. A colon requiring a type reports Identifier
796:   when the type name is missing; a later missing array or block delimiter
